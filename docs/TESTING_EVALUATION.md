# Testing and Evaluation Strategy

## Testing layers

### Frontend unit/component

Vitest + Testing Library:

- stage navigation and progress;
- intake states and validation messages;
- review actions preserve candidate and save reviewed value;
- dated/uncertain/undated rendering;
- symmetric discrepancy card;
- mask/export preview;
- empty/loading/partial/error/no-flags states;
- keyboard-visible controls and accessible names.

### Backend unit

Pytest:

- Pydantic contracts;
- amount/time/reference normalization;
- completeness and grouped discrepancy rules;
- alias/masking and safe logging;
- CSV serialization/formula protection;
- PDF view-model assembly;
- idempotency and state transitions;
- provider error mapping.

### Integration

- S3 upload intent conditions;
- S3 event -> source status -> observations using provider fakes;
- DynamoDB conditional writes/version conflict;
- export record -> S3 object;
- frontend mock/live client contract compatibility.

Use AWS-compatible test infrastructure only if it is already reliable; do not replace core unit tests with brittle emulation.

### End-to-end

Critical path only:

`load demo -> review correction -> timeline -> discrepancy -> export preview/download`

Later live smoke:

`create case -> presigned upload -> processing ready -> review -> export ready`.

## Golden fixture matrix

| Scenario | Expected |
|---|---|
| Empty input | Stable empty state, no invented observations |
| Clean image transaction | Correct fields/provenance, no missing flag |
| Missing reference | Observation retained + `MISSING_INFO` |
| Linked different amounts | Both retained + one grouped discrepancy |
| Unrelated different amounts | No discrepancy |
| Same digits/different namespace | No automatic link |
| Date only | Day interval, time unknown |
| Ambiguous slash date | Candidate interpretations + uncertain section |
| Relative time/no anchor | Unresolved, human verification |
| Duplicate bytes | Inventory retained, no double counting |
| Same amount/different currency | No direct amount discrepancy |
| Image provider malformed JSON | Source-level schema error, no invented claims |
| Sarvam timeout | Other sources remain usable |
| Unicode/multiline | Correct serialization |
| Formula-like cell | Neutralized in CSV |
| Planted PII | Absent from shareable view/PDF/CSV/log capture |
| Replayed event | No duplicate observations |
| Stale review version | 409/conflict, no overwrite |

Expected outputs are authored independently, not generated by production code.

## Evaluation metrics

Report separately:

- field extraction exact match, precision, recall per modality/field;
- flag precision/recall per rule with negative cases;
- provenance coverage = exported nonempty factual fields with resolvable references / all exported nonempty factual fields;
- contradiction preservation = conflicting claims retained / planted conflicting claims;
- uncertainty preservation = ambiguous/undated fixtures not made exact / all such fixtures;
- input accounting reconciliation;
- planted sensitive-string leakage count;
- deterministic ordering correctness;
- runtime and failure rate per modality.

Do not combine into one “accuracy” number. Describe fixture count, data generation, model/version/region, environment, and limitations.

## Performance checks

Measure after correctness:

- UI interaction/build size;
- status/list API latency for a representative small case;
- per-source processing latency by modality;
- export latency and size;
- deterministic engine at 100, 1,000, and optionally 10,000 observations.

No target is claimed passed until measured.

## Required verification commands

Exact commands are finalized after scaffolding, expected shape:

```text
frontend: lint, typecheck, test, build
backend: uv run ruff check, uv run mypy/pyright if configured, uv run pytest
infra: sam validate and reviewed deployment diff
```

Record actual commands/results in `STATUS.md`.
