# Scope Boundaries

## MUST

- React/shadcn complete mock workflow.
- Images/screenshots, PDF, text, and audio represented in intake and target backend.
- Stable source inventory and immutable provenance.
- Candidate extraction + human review.
- Dated, uncertain, and undated chronology.
- Missing, invalid, ambiguous, verification, discrepancy, duplicate, unsupported, and processing flags.
- Preserve all conflicting claims.
- Shared privacy view model.
- Safe structured CSV and readable PDF.
- Mock fallback and synthetic golden tests.
- Neutral, non-authoritative language.

## SHOULD

- Multi-page PDF hybrid text/render processing.
- Sarvam time-segment provenance.
- Reviewer-confirmed links.
- Partial retry.
- Responsive/keyboard WCAG-AA-oriented experience.
- Vercel/AWS synthetic deployment.

## COULD

- DOCX text input.
- Additional Indian-language fixtures.
- Reliable bounding-box highlighting.
- Reviewer notes.
- Larger stress evaluation.
- Authentication after requirements/privacy design.

## MUST NOT

- Determine fraud/scam/guilt, authenticity, admissibility, or legal conclusions.
- Submit to authorities/banks or imply official status.
- Fetch or score evidence URLs.
- Silently merge, discard, or resolve contradictory claims.
- Invent missing values or exact chronology.
- Use real victim data during the hackathon.
- Claim local/private processing when vendors receive content.
- Expose/log evidence, transcripts, secrets, provider payloads, or signed URLs.
- Add RAG, vector DB, agents, microservices, Kubernetes, event bus, charts, risk scoring, billing, collaboration, notifications, or dark mode.
- Let installed coding skills expand the scope.

## Cut order

Decorative motion -> extra inputs -> bounding boxes -> extra languages -> advanced sequence rules -> noncritical E2E. Never cut provenance, uncertainty, contradiction preservation, privacy/export safety, or mock fallback.
